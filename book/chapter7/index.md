# 第7章 模型后训练

## 先看结论

这一章讲的是：**把 Agent 运行时积累的经验，变成模型自己能学会的能力。**

前面的章节更多是在调系统。

这一章开始往前一步：把经验写回模型参数里。

## 什么是后训练

后训练可以简单理解成：

**先有一个基础模型，再用任务数据继续训练它。**

这样模型会更懂你想要的行为。

常见目标包括：

- 更会听指令
- 更会用工具
- 更符合任务风格
- 更少犯常见错误

## 为什么 Agent 适合做后训练数据来源

Agent 在真实使用时会留下很多有价值的信号：

- 用户怎么问
- 模型怎么想
- 它用了什么工具
- 它在哪一步出错
- 最后结果好不好

这些信息都可以变成训练材料。

所以 Agent 系统不只是应用层，它也是数据来源。

## SFT 是什么

`SFT` 可以先简单理解成：

**用标准答案来教模型学样子。**

比如：

- 该怎么回答
- 该怎么调用工具
- 该怎么整理输出

如果示范数据质量好，模型就更容易学到正确行为。

## 强化学习是什么

强化学习可以简单理解成：

**不是直接告诉模型答案，而是告诉它什么做法更好。**

它更像“试错后慢慢学会”。

在 Agent 场景里，这很有用，因为很多任务没有唯一标准答案，但有“做得更好”或“做得更差”。

## 从轨迹里学习

Agent 运行时会生成很多轨迹。

轨迹就是：

- 问题是什么
- 中间怎么想
- 调用了哪些工具
- 最后有没有成功

这些轨迹可以整理成训练数据，帮助模型学会更好的步骤。

## 数据质量很重要

后训练不是把所有日志都喂进去。

如果数据乱，模型也会学乱。

所以要注意：

- 去掉低质量样本
- 保留高价值样本
- 过滤错误轨迹
- 区分成功和失败案例

## 训练什么

后训练通常不是只训练“知识”。

更常见的是训练：

- 指令遵循
- 工具使用
- 推理步骤
- 输出风格
- 安全行为

也就是说，后训练更像在训练“做事方式”。

## 这一章里的难点

后训练有几个常见问题：

- 数据标注贵
- 奖励设计难
- 训练目标可能和真实任务不完全一致
- 过度优化某个指标会带来副作用

所以训练之前，评估设计很重要。

## 一个简单例子

如果你发现模型总是在调用工具前漏掉关键参数，你可以把这些失败案例整理出来。

然后用更好的示范来训练它。

这样模型下次就更可能按正确步骤执行。

## 这一章最想告诉你什么

Agent 系统的经验，不应该只停留在日志里。

它应该被整理、筛选、训练，再变成模型自己的能力。

## 记住一句话

后训练的目标，是把系统中的好经验变成模型参数中的真能力。
