# 后记

## 这章在说什么

后记是整本书的收尾。

它不是再讲一个新技术，而是回头总结：整本书到底在讲什么，Agent 以后又会往哪里走。

## 你可以这样理解

- 前面几章讲的是怎么搭一个 Agent。
- 中间几章讲的是怎么评估和改进它。
- 后面几章讲的是怎么让它更会交互、更会协作。

把这些放在一起看，你会发现这本书其实一直在讲同一件事：

**Agent 不是一个单独的模型，而是一整套系统。**

## 两个重点问题

后记里提到两个很重要的方向。

### 1. 实时交互

Agent 不能总是“等你说完，我再想很久”。

真实世界里的事情是连续发生的，所以 Agent 也要能更快、更自然地响应。

### 2. 持续学习

Agent 不能只会一次性回答。

它应该能从成功和失败里慢慢积累经验，变得越来越好。

## 一个简单例子

你可以把整个系统想成一辆车：

- 模型像发动机
- 上下文像方向盘和仪表盘
- 工具像轮子和刹车
- 评估像年检
- 进化像保养和升级

少了任何一部分，车都跑不稳。

## 这章最想告诉你什么

作者想说的是：

不要只盯着某一个模型、某一个框架、或者某一个 API。

真正重要的是整套方法：

- 看见什么
- 能做什么
- 怎么判断做得对不对
- 怎么让下次做得更好

## 记住一句话

后记不是结束，而是在提醒你：Agent 的核心，是一整套会不断进化的系统。
