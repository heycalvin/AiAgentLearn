# 引言

## 先看结论

这本书想讲的，不只是“AI 会聊天”，而是：

**AI Agent 是一个能理解目标、拆分任务、调用工具、完成工作的系统。**

引言的作用，就是先告诉你这本书为什么值得学，以及接下来十章会怎么讲。

## 这本书在解决什么问题

作者不是想再讲一次大模型是什么。

他更关心的是：

- 为什么有些 Agent 很聪明，但还是不好用
- 为什么有些系统看起来简单，却能稳定做事
- 为什么真正的能力，不只是模型本身

所以这本书的重点，不是单个模型，而是整套 Agent 设计。

## 为什么要学 Agent

因为现实里的任务，往往不是一句话就能完成的。

比如：

- 查资料
- 做总结
- 写代码
- 发邮件
- 调接口
- 处理多个步骤

如果只靠“问一句，答一句”，很多任务都做不完。

Agent 的价值，就是把这些零散动作串起来。

## 你可以这样理解

- 大模型像脑子，负责想
- 上下文像眼睛，负责看当前情况
- 工具像手脚，负责真的做事

这三个部分合在一起，才像一个完整的 Agent。

## 这本书为什么特别

作者想强调一件事：

**好的 Agent 设计，不会很快过时。**

因为真正重要的不是某个流行名词，而是底层规律：

- 怎么给模型信息
- 怎么让模型调用工具
- 怎么检查结果
- 怎么让系统持续变好

## 全书怎么安排

这本书大致分成三步：

### 1. 先理解 Agent 是什么

先建立基本概念，知道 Agent 到底是怎么工作的。

### 2. 再学怎么把它做出来

包括上下文、记忆、工具、代码生成这些核心部分。

### 3. 最后学怎么评估和进化

让系统不仅能跑，还能变得更稳、更强。

## 书里的一个重要观点

作者认为，很多现在看起来“新”的 Agent 设计，其实早就在真实项目里出现了。

也就是说：

- 实践往往先发生
- 名词后来才出现

这提醒我们，不要只追新词，更要看问题本身。

## 一个简单例子

如果你想做一个客服 Agent，你真正需要的不是“会说话”。

你更需要它：

- 记住用户说了什么
- 知道该调用什么工具
- 能按规则回答
- 出错时能恢复

这就是引言想带给你的起点。

## 记住一句话

这本书的重点，不是教你做一个会聊天的模型，而是教你做一个能稳定完成任务的 Agent。
