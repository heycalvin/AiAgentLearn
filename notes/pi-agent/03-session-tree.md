# 03 - Session Tree（会话树与存档/读档机制详解）

## 一、 为什么需要会话树？（痛点分析）

### 1. 传统线性对话的死胡同问题
在普通的 Chatbot（如网页版 ChatGPT/Kimi）中，对话记录是**单向线性数组** (`Array`)。
在 Agent 写代码的场景下，线性对话有一个致命缺点：
* 当 Agent 尝试 **【方案 A】** 失败后，报错信息和写坏的代码会被全量保存在历史记录中。
* Agent 尝试去修复报错，往往会越修越乱（“污染上下文”）。由于无法“擦除”错误的尝试，Agent 很容易陷入死胡同走不出来。

---

## 二、 什么是会话树（Session Tree）？

会话树相当于给 AI Agent 装备了**“游戏存档/读档系统（Save & Load System）”**。

```text
[Node 1: 用户需求: 编写斐波那契函数]
   ├── [Node 2: 方案 A - 暴力递归] 
   │    └── [Node 3: 报错 - 栈溢出失败] ❌ (发现走不通)
   │
   └── [Node 4: 方案 B - 动态规划] 👈 撤销(Undo)回 Node 1，开启新分支！
        └── [Node 5: 测试成功通过] ✅
```

### 核心机制
1. **节点 (Node)**：记录单次对话轮次（输入、决策、工具返回结果）。
2. **父子链 (Parent-Child Chain)**：每个节点指向其父节点。在生成记忆时，只需从当前游标节点（Current Head）反向追溯到根节点，即可生成干干净净的对话主线。
3. **读档撤销 (Checkout / Undo)**：当路线 A 失败时，将当前游标指针（Current Head）一键切回历史父节点 `Node 1`。

---

## 三、 主流 AI Agent 中的会话树体现

| 工具 | 实现名称 | 用户体验与底层原理 |
| :--- | :--- | :--- |
| **Cursor / Windsurf** | **Restore Checkpoint** | 改代码前自动打快照。点击 Restore 时，将本地文件恢复并把对话指针切回历史节点。 |
| **Pi Agent / Claude Code** | **Session Tree / Undo** | 底层原生树状存储，支持命令一键 `/undo` 回退节点与探寻新分支。 |
| **Cline (Roo Code)** | **Git Checkpoints** | 在改动前自动创建临时 Git Commit，撤销时执行 `git reset`。 |
| **网页 Chatbot** | **编辑历史消息** | 仅能在 UI 上开启新回答分支，但**无法同步撤销本地硬盘上的代码更改**。 |

---

## 四、 核心价值总结

会话树的核心灵魂是：**将“对话上下文节点”与“本地硬盘代码快照”绑定在一起，让 Agent 拥有随时低成本探索、随时无伤撤销试错的能力！**
