# 第4章 工具

![第4章配图](../../assets/ai-agent-book-illustrations/04-chapter4.png)

## 先看结论

这一章讲的是：**Agent 想真正做事，就必须有工具。**

没有工具，Agent 只能说话。
有了工具，它才能查、算、写、发、跑、协作。

所以，工具不是附加功能，而是 Agent 的手脚。

## 为什么工具这么重要

模型本身知道得再多，也不可能天然完成所有现实任务。

比如：

- 查天气
- 搜网页
- 读写文件
- 发邮件
- 调接口
- 跑代码

这些事情都需要工具。

也就是说，Agent 的能力，不只是“会想”，还要“会动手”。

## 工具可以分成三类

### 1. 感知工具

感知工具负责“看见外部世界”。

比如：

- 搜索网页
- 读取文件
- 识别图片
- 抓取网页内容

它们让 Agent 知道当前发生了什么。

### 2. 执行工具

执行工具负责“真的去做事”。

比如：

- 写文件
- 发消息
- 调用 API
- 创建任务
- 提交订单

它们让 Agent 从“说”变成“做”。

### 3. 协作工具

协作工具负责“和别人一起干活”。

比如：

- 发送协作请求
- 让另一个 Agent 接手
- 和人类确认下一步
- 共享状态和结果

复杂任务通常都需要协作，而不是单打独斗。

## MCP 是什么

这一章里很重要的一个词是 `MCP`。

你可以先把它理解成：

**一种让工具接入 Agent 的标准方式。**

它像一套统一接口，让模型更容易知道：

- 这个工具叫什么
- 它能做什么
- 输入是什么
- 输出是什么

标准化之后，工具就更容易复用，也更容易扩展。

## 工具调用的基本流程

一个典型的工具调用流程是：

1. Agent 先理解任务
2. 它决定要不要用工具
3. 它选一个合适的工具
4. 它把参数传给工具
5. 工具返回结果
6. Agent 再根据结果继续下一步

这就是很多 Agent 的基本工作方式。

## 异步 Agent

有些任务很快就能完成，比如查天气。

但有些任务很慢，比如：

- 跑一个大任务
- 等外部系统处理
- 等人类审批

这时候就需要异步方式。

异步的意思是：

- 不要傻等
- 先提交任务
- 之后再查看结果
- 期间可以继续做别的事

这会让 Agent 更像一个真正的工作系统。

## 怎么设计一个好工具

一个好工具通常要做到几件事：

- **职责单一**：一个工具只做好一件事
- **输入清楚**：参数格式要明确
- **输出稳定**：结果要容易被模型理解
- **失败可控**：出错时要能返回清晰信息
- **权限安全**：不能让模型随便做危险操作

如果工具太乱，Agent 也会跟着变乱。

## 一个简单例子

比如你让 Agent 帮你看今天的天气并发给同事。

它可能这样做：

1. 用天气工具查天气
2. 用总结工具整理一句话
3. 用消息工具发出去

这时候，Agent 不是一个“回答器”，而是一个“任务执行器”。

## 这一章最想告诉你什么

工具决定了 Agent 能碰到的世界有多大。

模型负责思考，工具负责触达现实。

两者结合起来，Agent 才真正有用。

## 记住一句话

工具让 Agent 从“会说”变成“会办事”。
