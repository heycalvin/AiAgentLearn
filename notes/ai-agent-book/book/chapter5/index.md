# 第5章 Coding Agent 与代码生成

![第5章配图](../../assets/ai-agent-book-illustrations/05-chapter5.png)

## 先看结论

这一章讲的是：**代码是最强的一种工具，而 Coding Agent 就是会用代码做事的 Agent。**

它不只是补全一句代码，而是能理解项目、修改文件、运行测试、检查结果。

## 为什么这章重要

代码很特别。

因为代码不仅是结果，它还是一种“创造新工具”的工具。

一个会写代码的 Agent，通常可以：

- 自动改项目
- 生成脚本
- 写测试
- 查 bug
- 帮人完成重复工作

这让 Agent 的能力一下子变强很多。

## Coding Agent 不只是写代码

很多人以为 Coding Agent 只是“自动补全”。

其实不是。

一个真正有用的 Coding Agent 通常要做完整流程：

1. 看懂需求
2. 理解项目结构
3. 找到相关文件
4. 设计修改方案
5. 改代码
6. 跑测试
7. 根据结果继续修

也就是说，它像一个真正的开发者，而不是一个打字机。

## 它需要哪些能力

### 1. 读项目

Agent 要先知道项目长什么样。

它要会看：

- 文件结构
- 依赖关系
- 当前代码风格
- 关键入口

如果看不懂项目，就很难改对。

### 2. 做修改

修改代码不是随便写几行。

它要知道：

- 改哪里
- 为什么改
- 会不会影响别的地方
- 要不要同步更新测试

### 3. 验证结果

写完以后，不能只看起来对。

还要：

- 跑测试
- 看报错
- 检查边界情况
- 确认功能真的可用

这一步很关键，因为代码世界里“看起来对”经常不等于“真的对”。

## 代码是 Agent 的放大器

一旦 Agent 会写代码，它就可以写出更多工具。

这就是为什么代码很强：

- 先写一个脚本
- 再写一个更好的脚本
- 再写一个自动化流程

能力会自己增长。

## 这一章会遇到的难点

Coding Agent 也会犯错。

常见问题包括：

- 改错文件
- 误解需求
- 忽略测试
- 引入新 bug
- 过度修改

所以它必须有检查和回滚思路。

## 工程上的关键点

好的 Coding Agent 通常需要：

- 清楚的上下文
- 有边界的修改
- 自动测试
- 错误反馈
- 版本控制

这些东西比“写得像不像人”更重要。

## 一个简单例子

比如你说：

“帮我给这个页面加一个搜索框，并修一下相关报错。”

一个靠谱的 Coding Agent 不会只输出代码。

它会：

1. 找到页面入口
2. 看现有组件
3. 改文件
4. 处理报错
5. 验证能不能运行

这才像真正的开发协作。

## 这一章最想告诉你什么

代码不是只给人写的。

代码也可以成为 Agent 的行动方式。

当 Agent 会理解、会修改、会验证时，它就不只是聊天模型，而是一个开发助手。

## 记住一句话

会写代码的 Agent，不只是会回答问题，而是能进入项目里真正帮你干活。
