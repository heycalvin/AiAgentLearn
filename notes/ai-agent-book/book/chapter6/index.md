# 第6章 Agent的评估

![第6章配图](../../assets/ai-agent-book-illustrations/06-chapter6.png)

## 先看结论

这一章讲的是：**你不能只觉得 Agent 很强，你还要真的测它到底强不强。**

评估就是给 Agent 做体检。

如果没有评估，就很难知道系统是真的变好了，还是只是看起来变好了。

## 为什么要评估

Agent 是一个会做事的系统。

它不是单次回答，而是连续行动。

所以你不能只看输出文字漂不漂亮，还要看它有没有真正完成任务。

你需要知道：

- 它成功了吗
- 它错在哪里
- 它会不会反复出错
- 它在不同任务上稳不稳定

## 评估要看什么

常见的评估维度有：

- **成功率**：任务完成了多少
- **正确率**：结果对不对
- **耗时**：做完要多久
- **成本**：用了多少 token 或计算资源
- **稳定性**：换个场景还行不行
- **可恢复性**：出错后能不能自己调整回来

这些指标放在一起看，才更接近真实体验。

## 离线评估

离线评估就是先准备一批任务，在固定环境里测试。

它适合回答这样的问题：

- 系统改完后是不是更好了
- 新版本有没有回归
- 哪种策略更有效

离线评估的好处是可控、可重复、方便对比。

## 在线评估

在线评估就是看真实用户在真实环境里的表现。

它更接近现实，但也更复杂。

因为真实世界里会有：

- 噪声
- 变化
- 意外情况
- 用户情绪

所以在线评估通常更难，但也更有价值。

## 任务环境

评估 Agent 的时候，环境很重要。

如果环境太简单，Agent 看起来会很强，但实际一上手就不行。

所以评估环境应该尽量接近真实任务。

## 评估指标

这一章强调，不要只看一个分数。

最好把多个指标一起看：

- 任务是否真的完成
- 过程是否合理
- 是否误用工具
- 是否浪费太多资源
- 是否有不安全行为

这样能更全面地理解 Agent。

## 统计显著性

如果你改了一个策略，成功率从 80% 变成 82%，这是不是“真的变好”？

不一定。

你还要看样本数够不够、波动大不大、差异是不是稳定。

这就是统计显著性的意义。

## 评估怎么帮助改进

评估不是最后一步，而是反馈入口。

一般流程是：

1. 设计任务
2. 跑评估
3. 看错误
4. 找原因
5. 改上下文、工具、提示词或模型
6. 再测一次

这会形成持续改进循环。

## 一个简单例子

如果一个客服 Agent 经常把退款和换货搞混，评估就能把这个问题找出来。

然后你可以继续看：

- 是提示词不清楚
- 是知识库没整理好
- 是工具输出不够明确
- 还是模型本身容易误判

这样改进才有方向。

## 这一章最想告诉你什么

Agent 不是靠感觉判断的。

要想把系统做稳，你必须把“好不好”变成可测量、可比较、可重复的东西。

## 记住一句话

没有评估，就没有可靠的改进。
