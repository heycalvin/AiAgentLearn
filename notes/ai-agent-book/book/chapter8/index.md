# 第8章 Agent的持续进化

![第8章配图](../../assets/ai-agent-book-illustrations/08-chapter8.png)

## 先看结论

这一章讲的是：**Agent 不应该只是做完任务，它还应该越来越好。**

持续进化的意思，就是让系统把每次运行中的反馈都变成下一次的改进。

## 什么叫持续进化

Agent 运行久了，会积累很多信息：

- 用户反馈
- 成功案例
- 失败案例
- 常见错误
- 有效流程

如果这些信息能被整理和利用，系统就会越来越成熟。

所以持续进化不是一个新功能，而是一个长期循环。

## 进化可以发生在哪些层

这一章的一个重要观点是：进化不一定非要先改模型。

它可以发生在很多层：

### 1. 记忆层

先更新它记住了什么。

比如：

- 用户偏好
- 常见任务
- 最近状态

### 2. 提示词和规则层

更新它应该怎么做。

比如：

- 新流程
- 新约束
- 新输出格式

### 3. 工具和技能层

增加它能做什么。

比如：

- 新工具
- 新脚本
- 新技能包

### 4. 模型层

最后才是把经验写进参数。

这通常成本更高，但效果也更深。

## 进化的基本循环

一个简单的进化循环是：

1. 收集运行数据
2. 找出失败和改进点
3. 更新规则、记忆或工具
4. 重新评估
5. 再上线

这个循环越稳定，Agent 就越可靠。

## 反馈信号从哪里来

反馈不一定要人工专门标注。

它可以来自：

- 用户点击
- 用户修改
- 任务是否完成
- 工具调用是否成功
- 人工审查

这些信号都能帮助系统进化。

## 为什么要分层更新

不是所有问题都要直接训练模型。

很多时候，先改上层更快更安全。

比如：

- 先修 prompt
- 再修工具参数
- 再修记忆
- 最后才考虑训练模型

这样更省成本，也更容易控制风险。

## 一个简单例子

如果一个 Agent 经常在同一种任务上出错，你可以先做几件事：

- 把错误步骤写进规则
- 增加一个提醒技能
- 把失败案例记到知识库
- 等以后数据够了再训练模型

这就是持续进化的思路。

## 这一章最想告诉你什么

Agent 的目标不是“一次做对”，而是“下次做得更好”。

真正成熟的系统，都会有自己的反馈闭环。

## 记住一句话

持续进化，就是让 Agent 把每次经验变成下一次更好的表现。
