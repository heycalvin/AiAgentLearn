# 第3章 用户记忆和知识库

![第3章配图](../../assets/ai-agent-book-illustrations/03-chapter3.png)

## 先看结论

这一章讲两件大事：

1. 让 Agent 记住用户
2. 让 Agent 用好外部知识

你可以把它理解成：

- 用户记忆 = 记住“你是谁、你喜欢什么、你发生过什么”
- 知识库 = 记住“这个领域里有哪些知识”

这两件事一起做，Agent 才会越来越像一个真正的助手。

## 这一章为什么重要

上一章主要讲的是单次对话里的上下文。

这一章往前走了一步，开始处理更难的问题：

- 对话结束后，Agent 怎么还记得你
- 用户下次再来时，Agent 怎么不从零开始
- 资料越来越多时，Agent 怎么还能找得准

所以，这一章是在讲“长期记忆”和“知识检索”。

## 一、用户记忆系统

### 1. 记忆不是照抄聊天记录

真正的记忆，不是把用户每句话都原封不动保存下来。

更好的做法是：

- 只保留未来可能有用的信息
- 把零散内容提炼成稳定事实
- 把信息整理成可以检索的结构

比如用户说：

“我喜欢靠窗座位，我是素食者。”

系统不需要记住整段原话，而是记住两个稳定事实：

- 座位偏好：靠窗
- 饮食偏好：素食

### 2. 先定义什么叫“好记忆”

书里先给了一个评估思路，分成三层：

- **基础回忆**：能不能准确记住一条明确事实
- **多会话检索**：能不能把不同时间、不同会话里的信息找全并串起来
- **主动服务**：能不能自己发现问题，并提前提醒用户

这三层很重要，因为它告诉我们，记忆系统不是“存进去”就结束了。

真正难的是：

- 记得准
- 找得全
- 能主动用起来

### 3. 记忆的层次

书里把 Agent 的记忆分成几个层次：

- **轨迹（Trajectory）**：当前这次对话的完整历史
- **用户长期记忆**：跨会话保存的稳定信息
- **业务状态**：任务处于什么阶段，比如“等待确认”“处理完成”

你可以这样理解：

- 轨迹像流水账
- 长期记忆像档案
- 业务状态像任务进度条

这样分层后，Agent 既能处理当前事情，也能记住长期信息。

### 4. 四种存储格式

这一章还讲了四种常见的记忆存法。

#### Simple Notes

最简单的方式。

每条记忆就是一个小事实，比如：

- 用户邮箱是某个地址
- 用户喜欢靠窗座位

优点是简单、便宜、好写。

缺点是信息关系会丢掉。

#### Enhanced Notes

比 Simple Notes 更完整。

它会保留一段上下文，让记忆更像一段小故事。

优点是信息更完整。

缺点是重复多、更新麻烦、检索也更重。

#### JSON Cards

把信息放进更结构化的层级里。

比如：

- `work.position.title`
- `personal.contact.email`

优点是好更新、好扩展。

缺点是太死板，复杂信息有时不好分类。

#### Advanced JSON Cards

这是更成熟的版本。

它不只是记一个事实，还会记：

- 背景
- 这个人是谁
- 和用户是什么关系
- 时间点是什么

这样就能更好地区分相似信息。

比如“张医生”这个词，如果没有背景，可能指不同的人。

### 5. 更进一步：用代码存记忆

这一章还介绍了一个很有意思的方向：把记忆变成可执行代码。

它的核心想法是：

- 用 Python 对象存状态
- 用 Python 函数写规则
- 让记忆不只是“能看”，还“能算”

这样系统就能直接做很多事：

- 统计去过几次国外
- 检查药物和过敏是否冲突
- 提醒护照是不是快过期了

这类能力，纯文本记忆很难稳定做到。

### 6. 更进一步：把记忆写进参数

书里还提到更前沿的方向：

- 把用户事实写入模型局部参数
- 或者把感知信息直接保存在模型内部的记忆结构里

你可以先不用记住所有名词。

只要记住一个方向就好：

**记忆可以从“外部文本”慢慢走向“内部结构”。**

### 7. 认知科学的启发

这一章借用了人类记忆的分类方法：

- **情景记忆**：具体发生过什么
- **语义记忆**：稳定知识和事实
- **程序记忆**：怎么做一件事

把它翻成 Agent 的语言，就是：

- 情景记忆 = 某次具体对话
- 语义记忆 = 用户长期偏好
- 程序记忆 = 反复形成的操作流程

这个视角很有帮助，因为它提醒我们：

记忆不只有一种，应该按用途分开设计。

### 8. 记忆框架案例

书里举了两个例子：

- **Mem0**：偏通用记忆流水线，重点是“提取、对比、更新”
- **Memobase**：偏用户画像和事件记忆，重点是把用户信息分成可管理的槽位

它们说明一个现实：

**工程上没有唯一答案，只有适合场景的方案。**

### 9. 记忆压缩与整理

记忆越积越多，就会变乱、变慢、变贵。

所以系统要做压缩和整理：

- 保留重要的
- 合并重复的
- 删除低价值的
- 把细碎内容提炼成摘要

这一步很像人类的遗忘和总结。

### 10. 隐私保护

记忆系统不只是技术问题，也是安全问题。

因为记忆里可能有：

- 电话
- 邮箱
- 医疗信息
- 交易信息

所以要做脱敏、权限控制和日志保护。

这点很重要，因为“记住得多”不等于“可以乱存”。

## 二、知识库和 RAG

### 1. RAG 是什么

RAG 的意思可以先简单理解成：

**先去找资料，再让模型回答。**

它的基本流程是：

1. 把资料切成小块
2. 把小块变成可检索的表示
3. 找到相关内容
4. 把结果放进上下文
5. 让模型生成答案

### 2. 为什么需要 RAG

因为模型不可能天生知道所有最新知识。

知识库可以补上这部分。

比如：

- 公司制度
- 产品文档
- 法规说明
- 最新网页内容

这些内容都很适合放进知识库。

### 3. 文档分块

RAG 的第一步通常是分块。

意思是把大文档切成小段，方便检索。

但分块也有问题：

- 切太碎会丢上下文
- 切太大又不好找

所以分块其实是在做平衡。

### 4. 稠密嵌入、稀疏嵌入、混合检索

这一章还讲了三种常见检索方式。

#### 稠密嵌入

更看重语义。

适合找“意思相近”的内容。

#### 稀疏嵌入

更看重关键词匹配。

适合找“字面上出现过”的内容。

#### 混合检索

把前两种结合起来。

这样通常更稳，因为既能看语义，也能看关键词。

### 5. 检索后再回答

一个最典型的 RAG 例子就是：

- 先搜到相关片段
- 再把片段放进模型上下文
- 最后由模型生成答案

这让模型可以利用它训练时没见过的新知识。

### 6. 多模态信息提取

知识不只有文字。

还可能在：

- 图表
- PDF 版式
- 图片
- 语音

这一章讲了三种路子：

- 直接用多模态模型理解
- 先转成文本再处理
- 先提取，再按需调用工具深入分析

你可以先记住一句话：

**看任务重要的是“保真度”和“成本”怎么平衡。**

### 7. 超越扁平文本

单纯切块加检索还不够。

更好的方法是把知识组织得更结构化。

书里提到的方向包括：

- 结构化索引
- 图结构知识
- 文件系统式组织
- 知识库时效治理

这些方法的核心目的都是一个：

**让知识更好找，也更好维护。**

### 8. 知识库的治理

知识库不是建完就结束。

它还会遇到：

- 过期
- 更新
- 下线
- 权限隔离

这就像一个长期运行的系统，必须有“管理规则”。

### 9. 智能体化 RAG

这是这一章里很重要的一步。

传统 RAG 比较像：

- 用户问一句
- 系统搜一次
- 直接回答

智能体化 RAG 更像一个研究员：

- 先想问题
- 再搜索
- 看结果够不够
- 不够就继续搜
- 直到信息足够再回答

这让检索从“被动流程”变成“主动工具”。

### 10. 上下文感知检索

有时候问题不在检索器本身，而在分块太粗。

比如一段“好的，就订这个吧”本身没有意义。

如果前文缺失，模型根本不知道“这个”指什么。

所以更好的做法是：

- 在分块前补充上下文
- 让每个块更容易被理解
- 提高检索准确率

### 11. 从数据集中提取深度知识

这一节讲的是更进一步的知识发现。

不仅是“找到文档”，还要从数据里整理出更深的知识。

这让知识库不只是搜索工具，也变成了知识建模工具。

## 三、这一章的核心总结

这一章最重要的结论是：

**最高级的用户记忆，不是单一技术，而是结构化记忆 + 精准检索一起工作。**

你可以这样记：

- 结构化记忆负责“概览”
- RAG 负责“细节”
- 两者结合，Agent 才能真正理解用户，也能真正用好知识

## 记住一句话

记忆解决“记住你”，知识库解决“知道更多”，而智能体化检索让它们真正变得可用。
