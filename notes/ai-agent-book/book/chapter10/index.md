# 第10章 多Agent协作

![第10章配图](../../assets/ai-agent-book-illustrations/10-chapter10.png)

## 先看结论

这一章讲的是：**当一个 Agent 不够用时，就让多个 Agent 一起协作。**

这就像一个小团队。

每个 Agent 分工不同，合起来完成复杂任务。

## 为什么要多 Agent

很多任务都不适合一个 Agent 全部包办。

比如：

- 调研
- 规划
- 写作
- 审核
- 执行

如果一个系统同时做这些事情，就很容易乱。

多 Agent 的好处是分工清楚。

## 常见分工方式

### 1. 规划者

负责看大目标，拆任务，排顺序。

### 2. 执行者

负责真正做事，比如查资料、写内容、跑工具。

### 3. 审核者

负责检查结果，找问题，防止出错。

### 4. 协调者

负责让大家对齐，决定下一步交给谁。

这样做的好处是，每个 Agent 只做自己最擅长的部分。

## 多 Agent 的协作模式

这一章介绍的核心不是“人多”，而是“怎么合作”。

常见模式包括：

- **主管-员工模式**：一个 Agent 负责总控，其他 Agent 执行子任务
- **分布式协作**：多个 Agent 平行工作，再汇总结果
- **讨论式协作**：不同 Agent 先讨论，再决定答案
- **分工流水线**：一个接一个完成步骤

不同任务适合不同模式。

## 协作时最重要的东西

### 1. 明确角色

每个 Agent 要知道自己是做什么的。

### 2. 共享状态

大家要知道任务做到哪一步了。

### 3. 清楚边界

谁负责什么，要说清楚。

### 4. 停止条件

不能一直讨论下去，必须知道什么时候该结束。

## 常见失败模式

多 Agent 不是天然更好。

它也会出问题，比如：

- 来回循环
- 互相重复
- 结果不一致
- 沟通成本太高
- 责任不清

所以协作系统必须有控制。

## Agent 社会

书里还提到一个更大的概念：`Agent 社会`。

你可以把它理解成：

**很多 Agent 一起组成一个更大的工作网络。**

有些像公司里的不同岗位，有些像互相协作的小团队。

这个方向很强，但也更复杂。

## 一个简单例子

如果你要做一份市场分析报告，可以这样分工：

- 一个 Agent 搜集资料
- 一个 Agent 整理数据
- 一个 Agent 写初稿
- 一个 Agent 检查错误

最后再把结果合在一起。

## 这一章最想告诉你什么

多 Agent 的价值不只是“多”，而是“分工更清楚，协作更灵活”。

但如果没有角色和边界，它也会变得混乱。

## 记住一句话

多 Agent 不是把任务分给更多人，而是把复杂工作拆成更清楚的协作关系。
